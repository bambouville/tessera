Aconcept & decisions to validate

WHAT IT IS

  • A floating, draggable puck the user parks anywhere on screen — like AssistiveTouch or a Messenger chat head.
  • Press & hold → 4 cardinal petals fade in. Slide to a direction, release → fires a macro into the active terminal.
  • Smart defaults per detected agent (Claude Code, Codex CLI, aider). Falls back to a configurable shell profile.
  • Down petal opens iOS on-device dictation (SFSpeechRecognizer, no network).

WHY IT EARNS A SPOT

  • In a Claude/Codex turn, ~90% of inputs are 1↵ / 2↵ / esc / "do X instead". The keyboard is overkill for the first three; dictation handles the fourth one-handed.
  • Bell-as-turn-complete already alerts you the agent is waiting. Swipe pad is the matched response primitive.
  • Single thumb-zone target on iPhone where there's no room for an accessory bar.
decisions baked in for v1:
resolved (v1): direction mapping. iOS convention — → approve · ← deny · ↑ always. matches system dialog ordering (confirm on the right, dismiss on the left) so muscle memory transfers from native alerts.
resolved (v1): gesture vocabulary. tap-hold-drag fires a directional macro, double-tap opens dictation, long-press relocates the puck. each primitive maps to one feature — no overloaded gestures.
resolved (v1): default petals. Claude Code & Codex ship with → / ← / ↑ bound only. the ↓ slot is hidden until the user configures a macro for it. dictation is a separate gesture, not a petal.
resolved (v1): app-match only. we query tmux #{pane_current_command} when the puck is touched. outside tmux, the shell fallback profile takes over. scrollback-regex matching parked for v2.

notes for review:
— direction mapping follows iOS convention: → approve · ← deny · ↑ always. confirm-on-the-right matches system alerts, share sheets, and message-action menus, so muscle memory transfers without retraining.
— gesture vocabulary: each primitive maps to one feature — no overloaded gestures. tap-hold-drag → macro · double-tap → dictation · long-press → relocate. discoverability via the small gesture-key callout in state 1, plus the gestures card in settings.
— default radial is 3 petals (→ / ← / ↑) for Claude Code & Codex. the ↓ slot is hidden until the user binds a macro to it — keeps the resting radial feel clean and removes the "what does down do?" learning tax for the common case.
— detection signal in v1 is pane_current_command only, queried via tmux -CC when the puck is touched. outside tmux mode, the shell fallback profile is used. scrollback-regex matching is parked for a future release.
— "always allow" semantics differ per agent: Claude Code's option 3 (3 ↵) is session-wide; Codex's p is per-command-pattern (e.g. "don't ask again for commands starting with date"). same gesture, agent-appropriate behavior baked into each profile.
— Codex uses single-key shortcuts without ↵ (y / p / esc), Claude Code uses number-plus-Enter. the rule model supports both — the macro field is just an opaque byte sequence.
— dictation activation via double-tap means voice has zero conflict with the radial: you can never accidentally fire a macro when you meant to speak. trade-off is reduced discoverability vs. a visible petal — addressed by the gestures card and a one-time first-run tooltip.
