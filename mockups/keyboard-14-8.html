Aresearch + decisions to validate

Six iPad terminals surveyed (Blink, Termius, Prompt 3, a-Shell, iSH, WebSSH). The patterns that pull their weight, plus the calls I want you to sign off on before I implement.

WHAT TO STEAL

  • Termius's drag-to-reorder + add-from-palette. Lowest cognitive load. We add a categorized palette (nav / mod / tmux / symbols) so users can discover chips, not just remember them.
  • Hardware-keyboard auto-hide. Already wired via GCKeyboard.coalesced. Free win.
  • Sticky-vs-one-shot modifier toggle. Termius shipped sticky but users hit lock-up bugs. Default to one-shot (Blink/Prompt convention) and let power users opt into sticky.
  • tmux operations stay native (⌘T / ⌘⇧W / ⌘1-9 / ⌘⇧[ / ⌘⇧]) and out of the chip system for v1. Adding macros now would couple the bar editor to tmux semantics before we know what users actually want — easier to add later than to remove.
  • Live preview inside the editor. Mirrors how Appearance shows top-bar-height changes — same metaphor, same trust.

WHAT TO SKIP

  • WebSSH-style config-file syntax. Powerful but opaque. Hard pass.
  • Swipe-on-canvas-for-arrows (Termius). Conflicts with our scroll dispatcher (§3.1) — pan recognizer already owns swipes for scrollback.
  • Per-host bar layouts. Tempting, but 99% of users want one good default. Defer until someone asks.
  • Multi-page bars / page-jump tokens. Horizontal scroll is enough for v1.
  • Remapping caps as any arbitrary key. Just ship caps→ctrl since that's the well-known unix-developer pain point. Full key remap is a v2 feature.
NEEDS YOUR APPROVAL — (1) one-shot is the default modifier behavior, with sticky as opt-in;   (2) the chip palette is split into 4 categories: nav, modifiers, F-keys, symbols — no tmux macros for v1; ship native ⌘-shortcut coverage and revisit once we have feedback;   (3) caps→ctrl is a single global toggle, no per-host override;   (4) reorder is via long-press → drag on any chip — no separate "rearrange" mode button — with a one-line hint surfaced in the editor.
