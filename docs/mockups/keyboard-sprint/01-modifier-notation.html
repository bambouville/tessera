modifier notation — glyphs vs words

One global preference that changes how every modifier key is written across the app. Flip the switch on the right: every surface below re-renders live, because in production they all route through one formatter instead of hard-coded "⌘⇧E" string literals. The point of this mock is coverage — the ten places the glyphs actually appear today.
Both decisions in §03 are settled: control unifies on ⌃, and words are hyphen-joined (cmd-shift-e).

03

the two decisions, settled

A · control unifies on ⌃  DECIDED

The bar's control chip rendered ^ — terminal caret notation — while the legend wrote ⌃. Glyph mode now uses ⌃ everywhere, so one app has one notation.

^ was ⌃ glyph mode ctrl words mode

The caret survives only where it is genuinely caret notation: the ^C and ^J chips send a literal control character and the shell echoes them that way, so they are unaffected by the setting in either mode.

B · words are hyphen-joined  DECIDED

Short lowercase vocabulary, joined with - — the tmux/emacs house style the audience already reads, and it sits better with the app's lowercase voice than Ctrl+Shift+E would.

⌘ ⌥ ⌃ ⇧cmd   opt   ctrl   shift ⇥ ↩ ⌫tab   ret   del ← ↓ ↑ →unchanged — arrows have no useful word form joiner-, letters stay lowercase: cmd-shift-e

One consequence to watch: the hyphen is also a literal key. A chord on the minus key renders cmd-- in words mode, so the formatter special-cases it to cmd-minus. Nothing in the shipped keymap binds it, but the recorder can produce it.

Cross-transport check: nothing here reaches the wire. Notation is display-only, so plain SSH, SSH+tmux, mosh, and mosh+tmux behave identically — the bytes AccessoryChipEncoder emits for a chip are keyed off the AccessoryChip case, never off displayLabel.
