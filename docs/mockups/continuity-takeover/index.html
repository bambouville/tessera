continuity — takeover overlay

When another device continues a live tmux-backed session, the device that lost the grid currently keeps rendering a size that no longer matches its screen — scaling artifacts. Proposal: the moment grid authority changes hands — an explicit @tessera_authority stamp the taking device writes on the tmux server — blur the terminal and show a frosted take-back card. Tapping it (or pressing any key) re-stamps authority, re-forces this device's size if it differs, and resyncs. The two devices below share one simulated tmux session — click through every transition live.

blur hides the mis-sized grid — feed stays live beneath detection: explicit stamp on the tmux server · %subscription-changed push · no P2P tap · or any key — takes control back symmetric: either device can yield / reclaim arms only for tmux launch modes — customCommand reconnects a fresh shell, nothing to take back

1 · Interactive demo — both devices, one session

Start state: the iPad owns session dev-1. On the iPhone, tap continue — the iPad yields and blurs. Tap the iPad's veil (or its take back control pill) to reclaim; the iPhone then yields in mirror. The scenario buttons inject the edge events. The same-grid iPad continues button simulates a third device whose grid matches this iPad's exactly — stamp-only detection, zero artifacts, instant take-back.

Entry is the existing Handoff continuation flow (the sessions-list row stands in for it), but detection never depends on it: the taking device writes the @tessera_authority stamp on the tmux server, which reaches the yielded device as a %subscription-changed push — same-grid takeovers included. A laptop's bare tmux attach writes no stamp and is caught by the size-mismatch fallback; a bare attach with an identical grid stays invisible, which is harmless — nothing mis-renders.

2 · State machine — per device, per session

Continuity presentation is a device-local state derived from one authoritative fact on the tmux server: the @tessera_authority stamp, written by whichever Tessera device last took the grid (in the same command batch as its resize) and pushed to every control client via a refresh-client -B subscription (%subscription-changed, tmux ≥ 3.2 — the same floor -f ignore-size already requires). There is no device-to-device channel: devices that may be countries apart coordinate through the one host both must be connected to anyway. tmux serializes the writes, so "current stamp ≠ mine" is the entire yielded test. A foreign %layout-change remains as fallback for stamp-less attachers (a laptop's bare tmux attach).

Transition table

#from → totriggerguard / notes
T1active → continued-elsewhere @tessera_authority stamp changes to another device (%subscription-changed push) size-independent — a same-grid second iPad still arms it, and the stamp names the taker for the card copy. Fallback for stamp-less attachers: a foreign %layout-change outside our clientSizeEpoch window, debounced so our own rotation / split-pane churn never triggers it
T2continued-elsewhere → reclaiming tap veil / take-back pill / any HW key keystroke that triggers reclaim is consumed, not forwarded; requires live connection
T3reclaiming → active geometry confirms: the active window's observed layout equals our viewport (checked at the claim fence ack and on every %layout-change) revised per TECHNICAL_REVIEW.md — a stamp ack can NOT prove geometry, since the stamp and tmux's window-size latest client state can disagree. The claim: refresh-client -C, then on inline SSH a no-op select-window on the current window (fixture-verified latest-client transfer; never resize-window inline); side channel keeps its direct window force. Veil lifts on settled geometry + one authoritative repaint. Same-grid reclaim settles at the fence ack — nothing waits on a %layout-change that will never come
T4reclaiming → continued-elsewhere stamp shows another writer again, or ack timeout (~3 s) the race: both devices reclaim at once — last writer wins, loser folds back to the overlay; no error dialog, the card simply returns
T5continued-elsewhere → active (auto) peer client detaches (%client-detached + list-clients corroboration — both parsed today) decision D3, tightened per review — auto-reclaim only when truly alone: list-clients on our session shows only this device's own clients (1 inline, 2 mosh topology), so a live bare laptop client is never seized from. Otherwise stay veiled until tapped. The same check clears a stale stamp left by a crashed peer at reconnect
T6any → reconnect overlay transport drops connection overlays outrank the continuity overlay; take-back pill disabled while offline. On reconnect, re-read the stamp (and size) — do not assume the pre-drop state
T7any → ended session exit / tmux window killed (from either device or host) existing ended UI wins; continuity overlay never masks an exit
T8(cold) → continued-elsewhere attach / foreground hydration reads a foreign stamp (or foreign size) enter blurred immediately — the mis-sized grid must never flash before the veil

Overlay priority stack (top wins)

  • 1 · ended — session is gone; nothing to take back.
  • 2 · connection overlays — reconnecting / auth; you can't reclaim a session you're not connected to. The continuity card stays visible beneath in its disabled variant (dimmed pill, amber host dot) so context isn't lost.
  • 3 · continuity veil — this proposal.
  • 4 · live terminal.

Corrected per TECHNICAL_REVIEW.md: normal SSH+tmux visible clients do NOT attach ignore-size (that geometry-preserving behavior was deliberately removed — active device wins); ignore-size is the mosh topology's visible-client trick. The @tessera_authority stamp is written in the same batch as the size commands and pushed via refresh-client -B (tmux ≥ 3.2), but it is advisory — it arms the peer's veil and names the taker. Geometry ownership is proven only by the observed window layout matching the claimant's viewport. The session itself is never evicted, matching today's "attached · other device stays attached" copy.

3 · Decisions to approve

D1

What arms the overlay

An explicit authority stamp, not a size heuristic. A second iPad with an identical grid still yields this device — zero artifacts, but two keyboards into one PTY is exactly the ambiguity the overlay removes, and behavior shouldn't depend on accidental geometry. The stamp names the taker, so the card says which device took over. Foreign-size fallback covers stamp-less attachers (bare tmux attach).

proposed: stamp-authority (explicit) + size fallback

D2

Reclaim gesture

Tap anywhere on the veil, the explicit pill, or any hardware key. The triggering keystroke is consumed. Accidental-tap cost is low: the other device just shows its own card and can tap right back.

proposed: tap anywhere · pill · any key

D3

Peer detaches while you're yielded

Auto-reclaim with a toast ("iPhone left — control returned here") versus staying blurred until tapped. Auto feels right: the session would otherwise sit blurred forever after you pocket the phone.

proposed: auto-reclaim + toast

D4

What shows beneath the blur

Keep the live (mis-sized) feed rendering under the veil — blur hides the artifacts and you still see activity ambient-style. Freezing the last good frame would look "right" but lie about liveness.

proposed: live feed, blurred

D5

Input while yielded

Terminal input is suppressed (tmux would happily interleave two keyboards into one PTY). Only the reclaim gesture is consumed. Scroll/find/tab-switch chrome stays disabled under the veil.

proposed: suppress all terminal input

D6

Scope of the veil

Per session, covering the whole terminal area including split panes; top bar stays (with an "on iPhone" chip). Other sessions on this device are untouched; the sidebar row for a yielded session gets the same device glyph.

proposed: session-scoped veil + top-bar chip

4 · Implementation notes (for after approval)

  • Authority is an explicit stamp on the server, not an inference — taking the grid writes set -w @tessera_authority <deviceName>:<gen> in the same command batch as refresh-client -C / resize-window; every control client subscribes via refresh-client -B and receives %subscription-changed pushes (tmux ≥ 3.2, the floor -f ignore-size already imposes). tmux serializes the writers, so "current stamp ≠ mine" is the entire yielded test — no consensus protocol, no proximity requirement, and it rides the connection the session needs to exist anyway. The already-parsed %client-detached + list-clients poll (dormant today behind .preserveServerGeometry) drive peer-departure T5; a foreign %layout-change outside our clientSizeEpoch window is the fallback for stamp-less attachers.
  • Handoff is a latency hint only — when the devices are in BT/Wi-Fi range, the continuation activity can carry a "taking over dev-1" flag so the yielded device pre-blurs before the first foreign event lands. Never the source of truth: Handoff is proximity-gated, and takeover can originate without it (synced host + same pinned tmux session opened from anywhere, or a laptop attach).
  • New presentation flag, not a new SessionState case — the five SessionState cases map 1:1 onto the top-bar connectivity dot; continued- elsewhere is a per-session presentation state on the live-session layer, orthogonal to connectivity.
  • Overlay mounts like SessionLaunchOverlay — a ZStack sibling inside the terminal stack (both the SSH and mosh mounts), so it veils only the terminal; top bar and sidebar stay interactive. The card uses the themed floatingGlass helper so it honors the user's chrome-material choice and Reduce Transparency. Blur composites fine over the SwiftTerm CAMetalLayer (XCUITest still sees black — verify via simctl screenshots as usual).
  • Reclaim is the "claim the active viewport" op (revised per TECHNICAL_REVIEW.md) — inline SSH: refresh-client -C + no-op select-window on the current window (the fixture-verified window-size latest transfer; resize-window must never leak inline — it can snap back under two visible clients and broadens one reclaim into server-wide resize churn). Side channel keeps the existing direct window force + forceFullRepaint(). The veil lifts only when the observed active-window layout equals our viewport (fence ack + every %layout-change re-check), then one authoritative repaint; the stamp ack is never the success condition. Same-grid reclaim settles at the fence ack. The manual refresh button invokes the same claim as its recovery role.
  • One invariant to make reversible — the existing (dormant) cede machinery documents hasCededGridOwnership as one-way for the session's lifetime; take-back control is exactly the transition it forbids, so that state becomes re-entrant.
  • iPhone parity — full parity; same states, compact card. The phone is expected to be the taker most often, but every state is symmetric.
