Terminal top bar — tab overflow window list

When tmux windows overflow the tab strip, touch scrolling fights the iPadOS window-drag region at the top edge. Proposal: keep the horizontal scroll exactly as-is (trackpad unchanged), and when the strip overflows, surface a chevron.down button — left of + — that opens a window list for direct touch selection.

chevron appears only on overflow strip geometry untouched — trackpad scroll identical landscape · portrait · Stage Manager widths 44pt touch rows in the list

1 · Interactive demo

This is live: scroll the tab strip, tap the chevron, pick a window, add tabs with +, close them with ×. Resize the viewport with the presets or the slider — the chevron appears and disappears with real overflow measurement, exactly as rotation or a Stage Manager resize would trigger it.

2 · Anatomy & spec

Overflow chevron

Byte-for-byte a chromeIconButton — the same component as +, find, files.

  • Symbol chevron.down, 14pt .medium
  • Box 28×24, radius 7 · hit frame 36pt wide × bar height
  • Color T.fgMuted; while menu is open: T.accent on T.accentSoft (isToggled)
  • Position after the tab strip, before + — inserted in the tmux branch of the bar's HStack only
  • Visibility only when strip content width > strip visible width (see rules below)
  • A11y id tmux-tab-overflow, label “Show all windows”

Window list

Floating glass panel anchored under the chevron, right-aligned. No scrim; tap-outside or Esc dismisses.

  • Panel width 288pt, radius 13, padding 5, hairline T.borderStrong, same glass material family as the pill; max-height ≈ 60% of screen, scrolls vertically
  • Row 40pt tall (+ padding ⇒ ≥44pt touch pitch), radius 9: window number mono 10.5 fgFaint · optional agent sparkles (amber = needs input, green = finished) · title mono 12.5, middle-truncated · ⌘N hint for windows 1–9 · a 28pt × affordance (the strip's 16pt close circle is itself hard to touch)
  • Active row T.accentSoft fill, title T.fg medium, hint T.accent — same ladder as the active tab capsule
  • Order tmux window order, identical to the strip
  • Footer “New window” row (same action as +) — optional, keeps one-handed flows in the menu
  • On select switch window and scroll the strip so the selected tab is visible (also fixes the existing ⌘1–9 no-scroll gap)

3 · States

A · Few windows — nothing changes

Strip fits ⇒ no chevron, no fades. Pixel-identical to today.

B · Overflow — chevron appears

Strip scrolls (trackpad unchanged); edge fade hints replace the hard clip; chevron slots in left of +.

4 · Behavior rules

RuleDetail
appearChevron shows when stripContentWidth > stripVisibleWidth + 2pt, measured via onGeometryChange on the ScrollView content vs container — so it reacts to rotation, Stage Manager resizes, Split View, Slide Over, and tab add/close/rename, with no orientation-specific code.
hysteresisShowing the chevron costs the strip 36pt, which could flap at the boundary. Once visible, it hides only when content would fit with the 36pt reclaimed (content ≤ visible + 36 − 2).
scroll unchangedThe strip keeps its exact geometry, scroll behavior, and hidden indicators. Trackpad and finger scrolling both still work; the menu is an additive affordance, not a replacement.
selectionMenu tap ⇒ tmux.selectWindow + close menu + scroll strip to reveal the tab (ScrollViewReader). Same reveal is applied to ⌘1–9 and palette switches — an existing gap this feature closes.
dismissTap outside, Esc, selecting a row, or rotating/resizing the window (popover-standard). State is ephemeral — never persisted.
rotationAnchored as a SwiftUI .popover-style overlay on the chevron; on size-class or geometry change it dismisses, and the chevron's visibility re-derives from the new measurement. Portrait simply overflows sooner — no special-casing.
close in listRow × routes through the same close path as the strip (incl. the pending-close confirm for busy panes). Row stays 40pt; × target 28pt.
degraded tmuxAmber ladder carries over: active row fill amber@0.16, hints amber — same as the strip's degraded styling.
transportsTabs exist only under tmux, so this covers SSH+tmux and mosh+tmux identically (one shared code path in tabStrip); plain SSH / plain mosh have no strip and are untouched.
iPhoneDeliberate decision: compact bar has no tab strip at all — window switching already goes through the session switcher — so the chevron is iPad-only by construction. Nothing to adapt.

Implementation lands entirely in SessionView.swift's tabStrip (≈ line 7697): one measured-width state, one chromeIconButton("chevron.down"), one overlay list reusing the tab model the strip already iterates. Edge fades are an optional half-day cosmetic (shown in the demo) and can be dropped without affecting the proposal.
