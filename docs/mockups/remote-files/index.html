Remote Files

A pwd-following remote file panel for Tessera — browse, transfer, preview, and share files on the connected host, across all four transports (SSH, SSH+tmux, mosh, mosh+tmux). One shared implementation: file operations never ride the terminal transport; they run on a dedicated per-host SSH/SFTP “file bridge”, mirroring the side-channel pattern mosh+tmux already uses.

Split panes: the panel follows the focused pane's cwd (tmux active pane in -CC modes). Switching session tabs swaps the whole panel context to that session's host — one panel instance, per-session state retained.

2 · Follow modes — how the panel tracks pwd

Three visible states. Following is the default; browsing away breaks the link (never fights the user); one tap re-syncs. When no cwd signal is available, the panel says so and offers the fix rather than silently going stale.

Following

~ / projects / dashboard

Panel root tracks the terminal's cwd live. cd in the shell, panel follows within a second. Source: tmux pane_current_path or OSC 7, per transport (§8).

Manual browse

/var/log/nginx

User navigated somewhere else — link shows broken, panel stays put while the shell moves. Tap the glyph to snap back to the terminal's cwd and resume following.

No cwd signal

~ · not following

Plain-SSH/mosh host whose shell doesn't emit OSC 7. Inline CTA: “Enable follow — install shell integration” appends a 3-line precmd snippet over the bridge (same consent flow as the existing install-key-to-host feature). Until then: manual browse from $HOME.

3 · Row actions — long-press menu, swipe, and defaults

Tap = preview (files) / expand (folders). Long-press = full context menu. Swipe leading = download, swipe trailing = share. Everything routes through the same five primitives: download, upload, preview, share, send-to-terminal.

  • Quick Look — streams to a temp file, opens the in-app previewer (§6). Images, PDF, video, text render natively.
  • Download — saves to On My iPad / Tessera / <host>/, visible in the Files app. Submenu: pick another folder.

5 · Share into Tessera — the Upload sheet

Tessera registers as a document handler, so it appears in every share sheet's app row (“Copy to Tessera”). The app opens with the Upload sheet: pick host, pick destination, go. Connected hosts sort first — sharing to a live session is two taps. Destination is a two-way choice: the session's cwd, or the temp location (~/.cache/tessera/) for files whose only purpose is to be referenced by path — picking temp auto-enables “paste path”, making share-to-temp the one-gesture “paste a file into the session” flow (§7). Never auto-connects: picking a disconnected host shows an explicit connect step.

6 · In-app preview & share out

Tapping a file streams it to a cache temp file and opens Quick Look (QLPreviewController) — the iOS built-in previewer. Images, PDF, video, audio, plain text, CSV, and Office docs all render with zero per-format code; pinch-zoom and multi-file swiping come free. Share/Open-In from the preview bar hands off to any installed app.

7 · “Paste” an image into Claude Code — feasible, with one twist

True Ctrl+V can't work: when Claude Code sees Ctrl+V it reads the clipboard of the machine it runs on — the remote host, which is headless and has no clipboard (and OSC 52 only syncs the other direction, host→terminal). But Claude Code auto-attaches image file paths that appear in the prompt (that's what drag-into-terminal does on desktop). So the equivalent flow is: upload the image to a host temp path over the file bridge, then inject the quoted path as terminal input. Pure keystrokes — works on every transport, and on any path-aware TUI, not just Claude Code.

8 · Implementation notes — high-level survey

8.1 · Architecture: one FileBridge per host, independent of transport

The hard constraint “every feature spans all four transports” is satisfied by never touching the terminal transport for file work. A FileBridge actor owns one dedicated SSH connection (Citadel) + SFTP subsystem per host, created lazily on first panel open or transfer, shared by all sessions/tabs on that host, torn down after idle timeout. This is the same shape as the mosh tmux side-channel that already exists (MoshSession.swift:994 — “Mosh's tmux side-channel is the only SSH connection that survives”), generalized and hoisted out of mosh-specific code. Auth reuses the session's credentials (KeyStore / Keychain) and the KnownHosts trust store — no new trust prompts for a host the user already trusts.

ConcernDesignStatus

8.5 · Risks & open questions

  • Huge directories — listDirectory on node_modules-scale dirs: paginate render, cap initial load (~2k entries + “load more”), sort off-main. No recursive prefetch, expand-on-demand only.
  • Background transfers — iOS suspends the socket shortly after backgrounding; v1 keeps transfers foreground-only with a clear paused/resume state (SFTP read/write offsets make resume natural). No URLSession background escape hatch for SSH.
  • ⌘⇧E — believed free (not in the known-reserved set: ⌘W, ⌃Tab, ⌘arrows, sim-eaten ⌘digits); confirm against the iPadOS shortcut HUD on hardware before shipping.
  • OSC 7 hostname mismatch — OSC 7 carries file://hostname/path; trust the path, ignore hostname (VPN/containers lie). Percent-decode carefully.
  • Permissions — no sudo story in v1: EACCES surfaces as a row badge + readable error. Root-owned file editing is out of scope.
  • Symlinks — resolve via getRealPath for navigation; show link glyph; guard against cycles with depth cap.
  • mosh fork drift — the OSC 7 patch adds one more delta to the vendored mosh; document in TESSERA-PATCHES.md alongside the existing patches and keep it minimal (Framebuffer string + dispatcher case, mirroring OSC 52).
  • Claude Code path detection — verify quoted-path + tilde behavior on a real session in M4; inject the absolute expanded path if ~ inside quotes isn't recognized.
